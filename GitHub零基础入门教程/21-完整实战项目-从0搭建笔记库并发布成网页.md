# 21 · 完整实战项目：从 0 搭建"我的学习笔记库"并发布成网页

> 前面的知识点是"零件"，这一篇把它们**组装成一件真东西**：一个分门别类的个人学习笔记库，**还能变成一个公网能访问的网页**。
> 跟着从头做完，你会同时用上：建仓库、文件夹组织、Markdown、commit、分支、Pull Request、GitHub Pages。这就是一份能写进简历、自己天天用得上的成果。

> 🧰 **这篇用 GitHub Desktop（第 20 章）演示**，全程几乎不碰命令行。会命令行的同学，每步括号里有对应命令。预计 1～2 小时，可以分几天做。

## 🎯 我们要做成什么

```
一个叫 my-study-notes 的仓库，结构像这样：

├── 英语/

│   └── Git学习笔记.md
└── 读书/
    └── 读书清单.md
```

完成后你会得到：一个**云端备份、有完整历史、随时随地能访问、还能发给别人看**的个人知识库。

## 阶段一：建好仓库（对应第 03/17/20 章）

### 1. 在 GitHub 网页建仓库

1. `➕ → New repository`。
2. **Repository name** 填 `my-study-notes`。
3. Description 填 `我的个人学习笔记库`。
4. 选 **Public**（这样以后能发布成网页）。
5. ✅ 勾上 **Add a README file**。
6. **Create repository**。

### 2. 用 GitHub Desktop 克隆到本地

1. 打开 GitHub Desktop → **File → Clone repository**。
2. 选 `my-study-notes`，选个本地位置，**Clone**。
3. 克隆完，**Repository → Show in Explorer/Finder**，打开这个文件夹。

> （命令行版：`git clone <地址>` 然后 `cd my-study-notes`）

---

## 阶段二：搭好文件夹结构 + 写第一篇笔记

### 3. 建分类文件夹和笔记文件

在文件夹里**像平时一样**新建子文件夹和文件（用资源管理器/访达，或任意编辑器）：

- 新建文件夹 `英语`、`编程`、`读书`。
- 在 `编程` 里新建文件 `Git学习笔记.md`。

> 💡 `.md` 文件用记事本就能建：新建文本文档，改名时把 `.txt` 也改成 `.md`。或者用 VS Code（第 11 章）更顺手。

### 4. 写点内容（Markdown，可直接抄）

把下面内容放进 `编程/Git学习笔记.md`：

```markdown
# Git 学习笔记 📝

> 记录我学 Git/GitHub 的过程和重点。

## 今天学会的命令

| 命令 | 作用 |
| --- | --- |
| `git add .` | 把改动放进暂存区 |
| `git commit -m "..."` | 存档 + 写说明 |
| `git push` | 上传到 GitHub |

## 我的理解
- Git 就像游戏的"存档系统"，每次 commit 是存一个档。
- GitHub 是放存档的"云盘 + 协作广场"。

## 还没搞懂的（待补充）
- [ ] 分支合并冲突到底怎么解决
- [x] add 和 commit 的区别
```

再随便给 `读书/读书清单.md` 写两本书、`英语/单词笔记.md` 写几个词，让结构充实起来。

### 5. 写好首页 README（整个库的"目录")

把仓库根目录的 `README.md` 改成一个导航页：

```markdown
# 📚 我的学习笔记库

> 我的个人知识库，持续更新。用 GitHub 管理，云端备份，永不丢失。

## 📂 分类目录

- 🇬🇧 [英语](./英语/)
  - [单词笔记](./英语/单词笔记.md)
  - [语法笔记](./英语/语法笔记.md)
- 💻 [编程](./编程/)
  - [Git 学习笔记](./编程/Git学习笔记.md)
- 📖 [读书](./读书/)
  - [读书清单](./读书/读书清单.md)

## 🔄 更新记录
笔记持续更新中，每次学到新东西就提交一次。
```

> 🔑 这个首页用了 Markdown 的**链接**语法 `[显示文字](路径)`，点击就能跳到对应笔记。这就是"用 README 当目录导航"，本教程仓库本身就是这么organize的。

## 阶段三：第一次提交并推送（对应第 20 章核心循环）

### 6. 在 GitHub Desktop 里提交

1. 切回 GitHub Desktop，**Changes 标签**里会列出你新建的所有文件夹和文件。
2. 点几个看看右侧的内容预览。
3. 左下 **Summary** 写：`搭建笔记库结构，新增 Git 笔记`。
4. 确认文件都勾选了，点 **Commit to main**。
5. 点右上 **Push origin** 上传。

> （命令行版：`git add .` → `git commit -m "搭建笔记库结构，新增 Git 笔记"` → `git push`）

### 7. 去网页欣赏成果

刷新 `github.com/你的用户名/my-study-notes`：

- 文件夹结构出现了；
- README 首页的目录导航能点击跳转；
- 点 "Commits" 能看到你的提交历史。

🎉 你的云端笔记库上线了！以后**每学到新东西 → 改/加笔记 → Commit → Push**，就这么简单。

## 阶段四：用"分支 + Pull Request"加一篇笔记（对应第 05/06 章）

平时自己记笔记直接提交 main 就行。但为了**练会专业工作流**，我们用分支 + PR 的方式加一篇笔记。

### 8. 新建分支

GitHub Desktop：**Current Branch → New Branch**，名字填 `add-reading-notes`，Create。

> （命令行：`git switch -c add-reading-notes`）

### 9. 在分支上加内容

在 `读书/` 里新建 `读书笔记-原则.md`，写几句读后感，保存。

### 10. 提交并发布分支

1. GitHub Desktop 里 Commit，Summary 写 `新增《原则》读书笔记`。
2. 点 **Publish branch**（把这个新分支推到 GitHub）。

> （命令行：`git push -u origin add-reading-notes`）

### 11. 发起 Pull Request

1. GitHub Desktop 会出现 **Create Pull Request** 按钮（或 Current Branch → Preview Pull Request），点它，**自动跳到浏览器**。
2. 在网页上填 PR 标题 `新增《原则》读书笔记`，写两句说明。
3. **Create pull request**。

### 12. 自己审查、自己合并

因为是你自己的仓库，你就是审查者：

1. 在 PR 页点 **Files changed**，看看新增了什么（绿色）。
2. 没问题，回 **Conversation** 标签点 **Merge pull request → Confirm merge**。
3. 合并后可以点 **Delete branch** 删掉这个分支。

> 🎓 你刚刚完整走了一遍**专业团队的工作流**：开分支 → 改 → PR → 审查 → 合并。这套流程在公司和开源项目里天天用，你已经会了！

### 13. 把合并后的 main 同步回本地

回 GitHub Desktop，**Current Branch 切回 main**，点 **Fetch/Pull origin** 把刚合并的内容拉回本地。

> （命令行：`git switch main` → `git pull`）

## 阶段五：把笔记库发布成网页（对应第 09 章）

让你的笔记库变成一个漂亮网页，手机上也能看。

### 14. 开启 GitHub Pages

1. 仓库网页 → **Settings → Pages**。
2. **Source** 选 **Deploy from a branch**。
3. **Branch** 选 `main`，文件夹 `/ (root)`，**Save**。
4. 往上找到 **Theme Chooser → Choose a theme**，挑一个喜欢的主题 → **Select theme**（它会自动提交一个配置文件）。

### 15. 访问你的网页版笔记库

等 1～3 分钟，访问：

```
https://你的用户名.github.io/my-study-notes
```

🎉🎉 你的 Markdown 笔记被渲染成了**带样式的网页**！README 的目录、各篇笔记都能在网页上漂亮地显示。把这个链接发给朋友，他们就能看你的笔记库了。

> 💡 因为开了 Pages，记得：以后 `Settings → Pages` 里有配置文件（`_config.yml`），别手贱删了。
