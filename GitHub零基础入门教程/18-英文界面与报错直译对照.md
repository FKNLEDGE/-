# 18 · 英文界面与报错直译对照（一看英文就慌？这篇治）

> GitHub 和 Git 满屏英文，小白一看就头大、不敢点。其实**翻来覆去就那些词**。这一篇把你会反复撞见的英文，按"在哪见到"分好类、直译成人话。
> **当字典用**：看到不认识的英文按钮或红字，回来查。

> 💡 先说一个根治办法：GitHub 网页能切中文！头像 → **Settings → Appearance → Language → 简体中文**。但 **Git 命令行的报错永远是英文**，所以这篇还是得备着。

## 二、Git 命令行的"状态词"（status 里常见）

敲 `git status` 时，这些词反复出现：

| 英文 | 中文 | 意思 |
| --- | --- | --- |
| **On branch main** | 在 main 分支上 | 你当前在 main 分支 |
| **working tree clean** | 工作区是干净的 | 没有未提交的改动，一切已同步 |
| **Untracked files** | 未跟踪的文件 | 新文件，Git 还没开始管它（需 `git add`） |
| **Changes to be committed** | 待提交的更改 | 已 `add`、进了暂存区，等着 commit |
| **Changes not staged for commit** | 未暂存的更改 | 改了但还没 `add` |
| **nothing to commit** | 没有要提交的 | 没改动 |
| **Your branch is up to date** | 你的分支是最新的 | 和远程同步了 |
| **Your branch is ahead of 'origin/main' by N commits** | 你的分支比远程多 N 个提交 | 你有 N 个提交还没 push |
| **Your branch is behind ... by N commits** | 你的分支比远程少 N 个提交 | 远程有更新，需要 `git pull` |

## 三、最常撞见的报错直译（附解法）

> 看到 `error`、`fatal`、`rejected` 别慌。`fatal` 在这儿不是"致命崩溃"，只是"这条命令没法继续"，改一下就行。

### 关于推送（push）

**`Updates were rejected because the remote contains work that you do not have locally`**
> 直译：推送被拒，因为远程有你本地没有的更新。
> 💊 解法：先 `git pull` 把远程更新拉下来（可能要解决冲突），再 `git push`。（第 07 章报错 1）

**`Support for password authentication was removed. Please use a personal access token`**
> 直译：不再支持密码认证，请使用个人访问令牌。
> 💊 解法：密码处填 **PAT 令牌**，不是登录密码。（第 02 章）

**`Authentication failed`**
> 直译：认证失败。
> 💊 解法：令牌/密钥不对或过期，重新配置。（第 02、07 章）

**`failed to push some refs`**
> 直译：部分引用推送失败。
> 💊 解法：通常和上面"远程有新东西"一起出现，先 `pull` 再 `push`。

### 关于合并 / 冲突

**`CONFLICT (content): Merge conflict in xxx`**
> 直译：内容冲突，xxx 文件里有合并冲突。
> 💊 解法：打开文件，删掉 `<<<<`/`====`/`>>>>` 标记，留你要的内容，再 `add` + `commit`。（第 05 章）

**`Automatic merge failed; fix conflicts and then commit the result`**
> 直译：自动合并失败，请解决冲突后再提交。
> 💊 解法：同上。想放弃合并：`git merge --abort`。

**`Please commit your changes or stash them before you merge/switch`**
> 直译：合并/切分支前，请先提交或暂存你的改动。
> 💊 解法：你有没提交的改动挡路了。先 `git commit`（保存），或学 `git stash`（临时收起来）。

### 关于仓库 / 路径

**`fatal: not a git repository (or any of the parent directories)`**
> 直译：这不是一个 Git 仓库。
> 💊 解法：你在错误的文件夹里敲 git 命令。`cd` 进正确的项目文件夹；新项目则 `git init`。（第 00、04 章）

**`fatal: repository '...' not found`**
> 直译：找不到这个仓库。
> 💊 解法：clone 的地址打错了，或仓库是私有的你没权限。检查网址、检查权限。

**`fatal: remote origin already exists`**
> 直译：远程 origin 已经存在了。
> 💊 解法：你重复添加了远程。一般不用管，或用 `git remote set-url origin <地址>` 改地址。

### 关于身份 / 配置

**`Please tell me who you are`** + `git config --global user.email "..."`
> 直译：请告诉我你是谁。
> 💊 解法：你还没配身份。照它给的命令设 `user.name` 和 `user.email`。（第 02 章）

### 命令本身的错

**`command not found`**
> 直译：找不到这个命令。
> 💊 解法：命令拼错了，或**把开头的 `$` 也敲进去了**，或软件没装。（第 00、16 章）

**`No such file or directory`**
> 直译：没有这个文件或目录。
> 💊 解法：文件/文件夹名打错，或你不在对的位置。用 `ls` 看有啥、`pwd` 看在哪、`Tab` 补全。（第 00 章）

**`permission denied`**
> 直译：权限被拒绝。
> 💊 解法：多数情况换成你自己的文件夹/仓库操作即可；SSH 相关则检查密钥配置。

## 四、提交/PR 评论里的英文黑话（社区缩写）

和老外协作或逛开源时，评论里常见这些缩写，认一下：

| 缩写 | 全称 | 意思 |
| --- | --- | --- |
| **LGTM** | Looks Good To Me | "我看没问题"，审查通过的口头禅 |
| **PR** | Pull Request | 拉取请求 |
| **WIP** | Work In Progress | 还在做、没完成，别合并 |
| **TODO** | To Do | 待办、待补充 |
| **FYI** | For Your Information | 供你参考 |
| **IMO / IMHO** | In My (Humble) Opinion | 依我看 |
| **AFAIK** | As Far As I Know | 据我所知 |
| **PTAL** | Please Take Another Look | 请再看一下（改完了） |
| **nit** | nitpick | 吹毛求疵的小建议（不强求） |
| **+1 / 👍** | —— | 赞成、我也要 |
| **ping** | —— | "戳一下"催回复 |
| **bump** | —— | 把沉了的帖子顶上来 |

## 五、看不懂就这么做

1. **切中文**：网页界面能切的都切了（Settings → Appearance → Language）。
2. **整行复制去搜**：报错的那行英文，原样复制到搜索引擎，前人多半遇到过。
3. **丢给 AI 翻译+解释**：把报错贴给 AI，让它"翻译并告诉我怎么解决"。
4. **抓关键词**：`rejected`(被拒)、`not found`(找不到)、`conflict`(冲突)、`failed`(失败)、`denied`(拒绝)——认得这几个核心词，错误类型就八九不离十。

> 🔑 **英文不是门槛，陌生才是。** 这些词翻来覆去就这么多，撞见几次你就脸熟了。别因为是英文就不敢点、不敢读。
