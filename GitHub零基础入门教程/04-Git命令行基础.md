# 04 · Git 命令行基础（在自己电脑上干活）

> 第 3 章你在网页上跑通了流程。这一章把同样的事搬到**自己的电脑 + 命令行**上完成。
> 核心就一句话要记住：**改完文件 → `add` → `commit` → `push`**。这四步，你以后每天都在重复。

---

## 一、先建立最重要的心智模型：三个区域

这是整个 Git 里**最该理解的一张图**。一个改动从"你手敲"到"传上云"，要经过三个区域：

```
   ①工作区              ②暂存区              ③本地仓库            ④远程仓库(GitHub)
 (Working Dir)        (Staging Area)       (Local Repo)        (Remote Repo)
┌───────────┐        ┌───────────┐        ┌───────────┐       ┌───────────┐
│ 你正在编辑 │ git add│ "这次要存  │ git    │ 已存档的   │ git   │  云端备份  │
│ 的文件     ├───────►│  哪些"的   ├───────►│  历史版本  ├──────►│  +协作中心 │
│           │        │  清单     │ commit │           │ push  │           │
└───────────┘        └───────────┘        └───────────┘       └───────────┘
                                                              git pull(反向下载)
```

用"**寄快递**"打个比方，瞬间就懂：

| 区域 | 快递比喻 | 对应命令 |
| --- | --- | --- |
| ① 工作区 | 你家里散落的、要寄的东西 | （你直接编辑文件） |
| ② 暂存区 | 你**挑进纸箱**、准备打包的那些 | `git add` |
| ③ 本地仓库 | **封箱贴单**、存档入库 | `git commit` |
| ④ 远程仓库 | **交给快递员**发出去 | `git push` |

> 🔑 **为什么 `add` 和 `commit` 要分两步？** 因为你一次改了 10 个文件，但可能只想把其中 3 个相关的打包成一次提交。`add` 就是"挑出这次要打包的"，`commit` 才是"封箱存档"。这种"挑选"的能力让你的历史记录更清晰。

## 二、把云端仓库下载到本地：`git clone`

我们用第 3 章建的 `my-notes` 仓库来练手。

1. 打开仓库主页，点绿色 **`< > Code`** 按钮，复制地址：
   - 用 **PAT 令牌**的选 **HTTPS** 地址：`https://github.com/你的用户名/my-notes.git`
   - 用 **SSH 密钥**的选 **SSH** 地址：`git@github.com:你的用户名/my-notes.git`

2. 打开命令行（Windows 用 Git Bash），先切到你想存放项目的文件夹，比如桌面：
   ```bash
   cd ~/Desktop
   ```

3. 克隆（下载）整个仓库：
   ```bash
   git clone https://github.com/你的用户名/my-notes.git
   ```

完成后，桌面会多出一个 `my-notes` 文件夹，里面是仓库的全部内容**和完整历史**。进去：

```bash
cd my-notes
```

> 💡 `clone` 和"下载 ZIP"的区别：ZIP 只是一堆死文件；`clone` 下来的是一个**活的 Git 仓库**，带着全部历史，能 commit、能 push、能和云端同步。

## 三、随时问 Git "现在什么情况"：`git status`

这是你**最该常敲**的命令，没有之一。它告诉你：现在哪些文件改了、哪些进了暂存区、哪些还没。

```bash
git status
```

刚 clone 完、什么都没动时，会显示：

```
On branch main
nothing to commit, working tree clean
```

（在 main 分支，没什么要提交的，工作区很干净）

> 📌 **小白习惯养成**：每做一步操作前后都 `git status` 一下，它会清楚地告诉你"接下来可以敲什么命令"。Git 的提示信息非常友好，别忽略它。

## 四、完整走一遍：改文件 → add → commit → push

现在我们在本地新建一个文件，把它一路推到 GitHub。

### 第 1 步：改点东西（动工作区）

新建一个文件 `日记.md`（你也可以直接用编辑器如 VS Code 打开 `my-notes` 文件夹来建）：

```bash
echo "# 我的第一篇命令行日记" > 日记.md
```

再 `git status` 看看：

```
Untracked files:
  (use "git add <file>..." to include in what will be committed)
        日记.md
```

红色的 `日记.md` 是 **Untracked（未跟踪）**——Git 发现了新文件，但还没把它纳入管理。

### 第 2 步：`git add`（挑进暂存区/纸箱）

```bash
git add 日记.md
```

> 💡 想把所有改动一次性都加进来，用 `git add .`（一个点表示"当前目录所有改动"）——这是日常最常用的写法。

再 `git status`，`日记.md` 变绿了，进入 **Changes to be committed（待提交）**——它已经在纸箱里了。

### 第 3 步：`git commit`（封箱存档）

```bash
git commit -m "新增第一篇命令行日记"
```

- `-m` 后面引号里就是 **commit message**（提交说明），和网页版那个框是一回事。
- 这一步把改动**永久存进了本地仓库**的历史里。

> ⚠️ 如果你忘了写 `-m "..."`，Git 会弹出一个叫 **Vim** 的编辑器让你写说明，很多小白会在这里"卡死出不来"。**逃生方法**：依次按 `Esc`，输入 `:q!`，回车，就能退出。然后老老实实带上 `-m` 重新提交。

### 第 4 步：`git push`（发快递到 GitHub）

```bash
git push
```

- 第一次 push 时，如果用 HTTPS，会弹出来问账号密码：**用户名输 GitHub 用户名，密码粘贴你的 PAT 令牌**（见第 2 章，不是登录密码！）。
- 成功后，刷新 GitHub 仓库网页，`日记.md` 就出现在云端了 🎉。

> 📌 有时第一次推送某分支，Git 会提示让你用 `git push -u origin main`。照着它给的命令复制粘贴执行即可。`-u` 是"建立关联"，设定后以后直接 `git push` 就行。

### 一张图记住这四步

```
   写/改文件        git add .        git commit -m"..."      git push
 ┌──────────┐    ┌──────────┐      ┌──────────┐         ┌──────────┐
 │  工作区   │───►│  暂存区   │─────►│ 本地仓库  │────────►│  GitHub  │
 └──────────┘    └──────────┘      └──────────┘         └──────────┘
   "我改了"       "选这些"          "存档+留言"           "传上云"
```

## 五、把云端的更新拉回本地：`git pull`

如果你**在别的电脑改了**、**在网页上改了**、或者**队友改了**云端的内容，你本地就落后了。用 `git pull` 把最新的拉下来：

```bash
git pull
```

> 🔑 **黄金习惯：每次开始干活前，先 `git pull` 一下。** 先同步到最新，再动手改，能避免大量"冲突"麻烦（冲突是什么，第 5 章讲）。

push 和 pull 是一对：

```
   本地  ── git push ──►  GitHub      （我的更新，传上去）
   本地  ◄── git pull ──  GitHub      （别人的更新，拉下来）
```

## 六、`.gitignore`：让 Git "无视"某些文件

有些文件你**不想**传到 GitHub，比如：

- 密码、密钥配置文件（`config.secret`、`.env`）——**传上去会泄密！**
- 软件自动生成的临时文件、缓存（`node_modules/`、`__pycache__/`、`.DS_Store`）——又大又没用。

办法：在仓库根目录建一个名叫 **`.gitignore`** 的文件（注意开头有个点），把不想要的文件名/文件夹写进去，**一行一个**：

```gitignore
# 井号开头是注释
.env                # 忽略环境变量文件
*.log               # 忽略所有 .log 结尾的文件
node_modules/       # 忽略整个 node_modules 文件夹
.DS_Store           # 忽略 Mac 的系统垃圾文件
```

写进 `.gitignore` 的文件，`git status` 就**当它们不存在**，`git add .` 也不会加它们。

> 💡 不用自己从零写。GitHub 建仓库时那个 "Add .gitignore" 下拉框，或者网站 **github.com/github/gitignore**，针对每种语言都有现成模板，直接抄。
> ⚠️ **重要**：`.gitignore` 只能拦住"还没被 Git 跟踪过"的文件。如果一个敏感文件**已经 commit/push 过了**，再加进 `.gitignore` 也删不掉云端的它——参见第 7 章"误传敏感文件"的处理。

## 七、看历史：`git log`

```bash
git log
```

会按时间倒序列出所有提交：

```
commit a1b2c3d4...   (HEAD -> main, origin/main)
Author: Li Xiaoming <xm@example.com>
Date:   Wed Jun 11 2026

    新增第一篇命令行日记
```

太长太啰嗦？用精简版（一行一条，强烈推荐）：

```bash
git log --oneline
```

```
a1b2c3d 新增第一篇命令行日记
e4f5g6h Initial commit
```

> 按 `q` 键退出 log 的浏览界面（如果它占满了屏幕）。

## 八、本章命令小结（你已经掌握日常 80%）

```bash
git clone <地址>        # 把云端仓库下载到本地（每个项目一次）
git status              # 看现在什么情况（最常用，随时敲）
git add .               # 把所有改动放进暂存区
git commit -m "说明"    # 存档并留言
git push                # 上传到 GitHub
git pull                # 下载 GitHub 上的最新更新
git log --oneline       # 简洁地看提交历史
```

> 🔑 把这 7 条记牢，配合一句口诀 —— **"拉、改、加、提、推"（pull → 改 → add → commit → push）** —— 就能应付绝大多数日常工作了。
