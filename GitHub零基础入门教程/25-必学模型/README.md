# 25 · 20 个必学模型（理解 Git/GitHub 的核心机制）

> "模型"在这里指**理解 Git 必须装进脑子的 20 个核心机制/心智模型**。它们是从 [第一性原理](../24-第一性原理.md) 落下来的具体抓手。
> 每个模型统一用四段讲：**是什么 → 解决什么 → 小白怎么理解（类比）→ 常见的坑**。读不懂公式没关系，**抓住类比就行**。

---

## 为什么是"模型"而不是"命令"

命令会变、会忘，但**模型一通百通**。你脑子里装的不该是"`git reset --soft HEAD~1` 这串字符"，而该是"撤销模型：历史是不可变快照链，所以能回到任意过去"。装好模型，命令自然就懂了，忘了一查就会。

---

## 🗂️ 20 个模型分三组

### 第一组 · 数据模型（Git 内部到底长啥样）→ [data-数据模型.md](./01-数据模型.md)

> 理解这 6 个，你就看穿了 Git 的"本质"，很多迷惑瞬间消失。

| # | 模型 | 一句话 |
| --- | --- | --- |
| 1 | **快照模型** | Git 存的是每次的"完整快照"，不是"改了啥" |
| 2 | **三区域模型** | 工作区 / 暂存区 / 本地仓库，改动逐级流动 |
| 3 | **哈希与内容寻址模型** | 用内容算出的指纹当身份，相同只存一份、防篡改 |
| 4 | **提交图模型（DAG）** | 提交靠"父指针"串成一张有向无环图 |
| 5 | **引用即指针模型** | 分支/HEAD/标签都只是"指向某提交的便利贴" |
| 6 | **分布式仓库模型** | 人手一份完整仓库，远程只是约定的同步点 |

### 第二组 · 操作模型（日常每一步在干啥）→ [operation-操作模型.md](./02-操作模型.md)

> 这 8 个覆盖你 95% 的日常动作。

| # | 模型 | 一句话 |
| --- | --- | --- |
| 7 | **暂存-提交模型** | add 是"挑进纸箱"，commit 是"封箱存档" |
| 8 | **推拉同步模型** | push 上传、pull 下载、fetch 只看不合 |
| 9 | **远程跟踪模型** | `origin/main` 是"云端那条线在本地的影子" |
| 10 | **分支隔离模型** | 开分支 = 开一个零成本的平行宇宙 |
| 11 | **三方合并模型** | 比对"共同祖先+双方"，能自动合就自动合 |
| 12 | **变基模型（rebase）** | 把分支"搬到"新基点，让历史变直线 |
| 13 | **冲突裁决模型** | 改了同一处，机器停下让你这个裁判定 |
| 14 | **撤销/时光机模型** | restore/reset/revert/reflog 各管一段后悔 |

### 第三组 · 协作与工程模型（多人和自动化）→ [collaboration-协作工程模型.md](./03-协作工程模型.md)

> 这 6 个让你从"自己用"升级到"团队/开源/工程化"。

| # | 模型 | 一句话 |
| --- | --- | --- |
| 15 | **Fork-PR 模型** | 没权限也能贡献：复制一份→改→申请合并 |
| 16 | **工作流模型** | GitHub Flow / Git Flow / 主干开发，团队的交规 |
| 17 | **代码审查模型** | 合并前有人逐行把关，质量与传承 |
| 18 | **Issue/项目管理模型** | 用工单、标签、看板把"要做的事"管起来 |
| 19 | **自动化模型（CI/CD/Hooks）** | 事件触发，机器自动测试/部署/检查 |
| 20 | **发布与版本模型** | Tag/Release + 语义化版本号 `v1.2.3` |

> 💡 **学习顺序建议**：先把第一组（数据模型）的 1、2、5 啃透（快照、三区域、指针），它们是理解一切的钥匙；其余用到再回来查。**不必一次背完 20 个。**

## ✅ 学完这 20 个模型，你应该能答

1. 为什么说分支"很轻"？开一个分支 Git 在内部其实只做了什么？（模型 5、10）
2. `merge` 和 `rebase` 都能合并，有什么本质区别？各自适合什么时候？（模型 11、12）
3. `reset`、`revert`、`restore` 三个"撤销"分别在什么场景用？（模型 14）
4. 我没有某项目的写权限，怎么给它贡献代码？（模型 15）
5. 一个团队为什么要约定"工作流"？GitHub Flow 大概是怎样的？（模型 16）
