# 19 · "我想做 X 怎么办"——任务反查速查

> 前面的章节是"按知识点"组织的。但你干活时往往是**带着一个具体目的**来的："我就想把这个文件传上去，该点哪/敲啥？"
> 这一篇**按你的目的反查**：找到你想做的事，直接给你三种方式的最短路径——**网页 🖱️ / 命令行 ⌨️ / VS Code 🧩**，并指到详细章节。

> 用法：`Ctrl+F`（网页里搜索）输入你想做的事的关键词，跳到那一条。

---

## 🟢 入门第一步

### 我想……把电脑里一个现成项目放到 GitHub 上

- 🖱️ **网页**：先在 GitHub `New repository` 建个**空**仓库（**别勾** README）→ 按页面给出的 "push an existing repository" 几行命令照抄。
- ⌨️ **命令行**：进项目文件夹 → `git init` → `git add .` → `git commit -m "首次提交"` → `git branch -M main` → `git remote add origin <仓库地址>` → `git push -u origin main`。
- 🧩 **VS Code**：打开文件夹 → 源代码管理面板 → **Publish to GitHub**（一键发布）。
- 📖 详见：04 章 / 11 章

### 我想……把 GitHub 上的项目弄到电脑上

- 🖱️ 绿色 `Code` → **Download ZIP**（只要文件）。
- ⌨️ `git clone <地址>`（要能同步/提交，**推荐**）。
- 🧩 命令面板 `Git: Clone`。
- 📖 详见：04 章三、15 章

## 📤 日常：保存与上传改动

### 我想……把我改的东西保存并传上 GitHub

> 这是最高频操作，口诀：**拉、改、加、提、推**。

- ⌨️ `git pull` → 改文件 → `git add .` → `git commit -m "说明"` → `git push`
- 🧩 改文件 → 源代码管理面板点 `+` 暂存 → 写信息点 ✓ → 点 🔄 同步
- 🖱️ 直接在网页上编辑文件 → `Commit changes`（适合小改）
- 📖 详见：04 章、11 章、17 章

### 我想……只上传某几个文件，不是全部

- ⌨️ `git add 文件1 文件2`（只 add 想要的）→ `commit` → `push`
- 🧩 在源代码管理面板里**只点你要的那几个文件**的 `+`
- 📖 详见：04 章

### 我想……让 Git 别管某些文件（如密码、缓存）

- 建一个 `.gitignore` 文件，把不想要的文件名/文件夹写进去，一行一个。
- ⚠️ 已经传过的文件，加进 `.gitignore` 也删不掉历史里的，得额外处理。
- 📖 详见：04 章六、07 章（误传敏感文件）

## 🌿 分支相关

### 我想……开一个新分支去试验，不影响主线

- ⌨️ `git switch -c 新分支名`
- 🧩 点左下角分支名 → `Create new branch`
- 🖱️ 仓库页分支下拉框输入新名字 → `Create branch`
- 📖 详见：05 章

### 我想……把做好的分支合并回 main

- ⌨️ `git switch main` → `git merge 分支名`
- 🖱️（团队推荐）推上去后发 **Pull Request**，审查通过再合并
- 📖 详见：05 章、06 章

### 我想……切到另一个分支看看

- ⌨️ `git switch 分支名`
- 🧩 点左下角分支名，从列表选
- 📖 详见：05 章

### 我想……删掉一个用不到的分支

- ⌨️ `git branch -d 分支名`（本地）；`git push origin --delete 分支名`（删远程的）
- 📖 详见：05 章

## 🤝 协作 / 开源

### 我想……给一个不属于我的开源项目贡献代码

- 流程：**Fork**（网页点）→ `git clone` 你的 Fork → 开分支改 → `push` → 发 **Pull Request**
- 📖 详见：06 章三（七步完整实战）

### 我想……报告一个 bug 或提个建议

- 🖱️ 项目页 **Issues → New issue**，写清标题、复现步骤、期望/实际结果
- 📖 详见：06 章五

### 我想……让别人能一起改我的仓库

- 🖱️ 仓库 **Settings → Collaborators → Add people**，输对方用户名邀请
- 📖 详见：06 章一

### 我想……把别人 PR 里的修改合并进来

- 🖱️ PR 页面 → 看 `Files changed` 审查 → **Merge pull request**
- 📖 详见：06 章四

## ⏪ 出错了 / 想反悔

### 我想……撤销还没提交的修改（改乱了想还原）

- ⌨️ `git restore 文件名`（丢弃工作区改动）
- 🧩 源代码管理面板里该文件右键 → **Discard Changes**
- 📖 详见：07 章①

### 我想……取消刚才的 git add（撤出暂存区）

- ⌨️ `git restore --staged 文件名`
- 🧩 在 "Staged Changes" 里点文件的 `−`
- 📖 详见：07 章②

### 我想……改最近一次提交的说明（写错字了）

- ⌨️ `git commit --amend -m "正确的说明"`（**前提：还没 push**）
- 📖 详见：07 章③

### 我想……撤销最近一次提交

- 还没 push：⌨️ `git reset --soft HEAD~1`（保留改动）
- 已经 push：⌨️ `git revert <提交ID>`（加一个反向提交，最安全）
- 📖 详见：07 章④⑤

### 我想……找回好像被我搞丢的提交

- ⌨️ `git reflog` 找到那一步的 ID → `git reset --hard <ID>`
- 📖 详见：07 章场景 C

### 我想……回到几天前那个能正常用的版本看看

- ⌨️ `git log --oneline` 找 ID → `git switch -c 回看分支 <ID>`
- 📖 详见：07 章场景 B

### 我想……解决 push 时"被拒绝"的报错

- ⌨️ `git pull`（拉下远程更新，可能要解决冲突）→ `git push`
- 📖 详见：07 章报错 1、18 章

## 🔧 账号 / 设置

### 我想……把 GitHub 界面变成中文

- 🖱️ 头像 → **Settings → Appearance → Language → 简体中文**
- 📖 详见：17 章步骤 5、18 章

### 我想……把仓库从公开改成私有（或反过来）

- 🖱️ 仓库 **Settings → 最底部 Danger Zone → Change visibility**
- 📖 详见：14 章一

### 我想……不让提交暴露我的真实邮箱

- 🖱️ Settings → Emails → 勾 "Keep my email addresses private"，把 `git config user.email` 设成给你的 noreply 邮箱
- 📖 详见：14 章一

### 我想……删掉一个仓库

- 🖱️ 仓库 **Settings → 最底部 Danger Zone → Delete this repository**（⚠️ 不可逆）
- 📖 详见：14 章三
