# 03 · 你的第一个仓库（全程网页操作，零命令行）

> 这一章**一行命令都不用敲**，全程在 GitHub 网页上点鼠标。目标：让你**亲手跑通一遍完整流程**——建仓库 → 看懂 README → 改文件 → 提交 → 上传文件 → 看历史。
> 跑通这一遍，你就对"GitHub 到底怎么用"有了实感，后面学命令行就只是"换个方式做同样的事"。

---

## 一、创建你的第一个仓库

仓库（Repository / Repo）= 一个被 Git 管理的"项目文件夹"。我们来建一个放"个人学习笔记"的仓库。

1. 登录 GitHub，点右上角 **➕ → New repository**。
2. 填写表单：

   | 选项 | 填什么 | 说明 |
   | --- | --- | --- |
   | **Repository name** | `my-notes` | 仓库名，英文/数字/连字符，别用空格和中文 |
   | **Description** | `我的学习笔记` | 一句话简介，选填 |
   | **Public / Private** | 新手选 **Public** | Public 公开谁都能看；Private 私有只有你能看。学习用 Public 即可 |
   | **Add a README file** | ✅ **勾上** | 勾上它会自动生成一个 README，仓库才不是空的 |
   | **Add .gitignore** | 暂时不用选 | 后面第 4 章讲它干嘛的 |
   | **Choose a license** | 暂时不用选 | 开源协议，以后再说 |

3. 点 **Create repository**。

🎉 恭喜，你的第一个仓库诞生了！网址是 `github.com/你的用户名/my-notes`。

---

## 二、看懂仓库主页的每个部分

建完仓库你会看到项目主页，对照着认一认：

```
┌──────────────────────────────────────────────────────────┐
│  用户名 / my-notes              ⭐Star  👁Watch  🍴Fork    │ ← 仓库名 + 互动按钮
├──────────────────────────────────────────────────────────┤
│  [Code] [Issues] [Pull requests] [Actions] [Settings] ... │ ← 功能标签页
├──────────────────────────────────────────────────────────┤
│  🌿 main ▾        [<> Code ▾]  ← 绿色按钮：下载/克隆用      │
│  ┌────────────────────────────────────────────────────┐  │
│  │ 📄 README.md      初始提交        刚刚                │  │ ← 文件列表
│  └────────────────────────────────────────────────────┘  │
│  ┌────────────────────────────────────────────────────┐  │
│  │  # my-notes                                         │  │ ← README 自动显示在下方
│  │  我的学习笔记                                         │  │
│  └────────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────────┘
```

几个关键点：

- **README.md**：项目的"门面/说明书"。GitHub 会自动把它显示在仓库主页下方。**它是访客了解你项目的第一眼**，所以值得好好写。
- **绿色 `Code` 按钮**：点开能看到 HTTPS / SSH 两种地址（第 4 章 clone 时用）和"Download ZIP"（直接下载整个项目压缩包）。
- **🌿 main**：当前所在的**分支**，默认叫 `main`（第 5 章详讲）。
- **Star / Fork**：收藏 / 复刻别人的项目时会用到（第 6 章）。

## 三、README 是什么？为什么它是 `.md` 文件

README 用的是 **Markdown** 格式（文件后缀 `.md`）——一种**用纯文本写出排版效果**的轻量语法，GitHub 上到处都是它。常用语法就这几条：

| 你写的 | 显示效果 |
| --- | --- |
| `# 一级标题` | 大标题 |
| `## 二级标题` | 中标题 |
| `**加粗**` | **加粗** |
| `*斜体*` | *斜体* |
| `- 列表项` | • 列表项 |
| `` `代码` `` | 等宽高亮的 `代码` |
| `[文字](网址)` | 可点击的链接 |
| `![](图片网址)` | 显示一张图片 |

> 💡 你正在读的这份教程，全部就是用 Markdown 写的。学会它，你写笔记、写文档、写项目说明都用得上，**是性价比极高的技能**。

## 四、在网页上修改文件（你的第一次提交 Commit）

我们来把 README 改得丰富一点，**亲历一次"提交"**。

1. 在仓库主页点开 **README.md** 文件。
2. 点右上角的**铅笔图标 ✏️（Edit this file）**。
3. 把内容改成：

   ```markdown
   # 我的学习笔记 📚

   这是我的第一个 GitHub 仓库，用来存放学习笔记。

   ## 目录
   - Git 与 GitHub 入门
   - Markdown 语法
   - 读书笔记

   > 持续更新中……
   ```

4. 改完后，往下拉到底部，会看到一个 **Commit changes（提交修改）** 的框，这就是关键一步：

   ```
   ┌─ Commit changes ──────────────────────────────┐
   │  ① 标题：完善 README，添加目录          ← 必填   │
   │  ② 描述：（可选，写详细说明）                    │
   │                                                │
   │  ◉ Commit directly to the main branch          │
   │  ○ Create a new branch for this commit...      │
   │                                                │
   │            [ Commit changes ]  ← 点这个         │
   └────────────────────────────────────────────────┘
   ```

   - **① 提交标题**：用一句话说清"这次改了什么"，比如 `完善 README，添加目录`。这就是 **commit message（提交信息）**。
   - 选 **Commit directly to the main branch**（直接提交到主分支）。
   - 点 **Commit changes**。

🎉 你刚刚完成了一次 **Commit（提交/存档）**！这次修改被永久记录了下来，附带你写的说明、时间、作者。

> 🔑 **为什么 commit message 这么重要？** 三个月后你回来看历史，一排 `更新了一下`、`改改改`、`123` 这种信息等于没写。好的提交信息是**写给未来的自己和队友看的**。原则：**一句话说清"做了什么"**，比如"修复登录按钮失效"、"补充第三章数据"。

## 五、查看你的"提交历史"（时光机就在这）

回到仓库主页，点文件列表上方的 **"X Commits"**（提交次数，可能显示个时钟图标或 commit 数）。你会看到一条历史记录：

```
●  完善 README，添加目录        你, 刚刚
●  Initial commit               你, 几分钟前
```

点任意一条，能看到**那次到底改了哪些行**：

```
  # 我的学习笔记 📚                    ← 你新增的行会标绿、前面带 +
- 旧的内容                            ← 删掉的行会标红、前面带 -
+ ## 目录                            ← +
+ - Git 与 GitHub 入门                ← +
```

> 这就是第 1 章说的"时光机"。**每一次 commit 都被完整记录，绿色是新增、红色是删除，一目了然**。再也不用 `最终版_真的最终.doc` 了。

## 六、上传已有文件（拖拽即可）

想把电脑里现成的文件（比如一张图片、一个 PDF 笔记）放进仓库？

1. 仓库主页点 **Add file ▾ → Upload files**。
2. 把文件**直接拖进**网页的虚线框里（或点击选择文件）。
3. 下方同样填一个 commit message，比如 `上传第一章读书笔记`。
4. 点 **Commit changes**。

文件就进仓库了，同样会留下一条提交历史。

> 💡 也可以用 **Add file → Create new file** 在网页上直接新建文件：在文件名框里输 `读书笔记/第一章.md`，**输入 `/` 就会自动创建文件夹**，很方便。

## 七、回顾：你刚刚学会的，正是日常 80% 的操作

你全程没敲一行命令，但已经完成了 GitHub 的核心循环：

```
新建/编辑文件  ──►  写 commit message  ──►  Commit（存档）  ──►  在历史里随时回看
```

第 4 章我们会用**命令行**做**一模一样的事**，区别只是：

- 网页版适合**小修小改、随手记录**；
- 命令行 / 桌面版适合**在自己电脑上大量干活**，改完一次性同步。

二者底层完全一致，所以这一章建立的直觉，后面全都用得上。

## ✅ 本章自测 / 练习

1. 自己再建一个仓库 `my-first-website`，在 README 里用 Markdown 写：一个一级标题、一段加粗文字、一个三项的列表、一个指向 GitHub 的链接。
2. 把这个 README 修改两次，每次写清楚 commit message，然后去"提交历史"里查看这两次分别改了哪些行。
3. 上传一张你喜欢的图片到仓库，并在 README 里用 `![](图片文件名)` 把它显示出来。
