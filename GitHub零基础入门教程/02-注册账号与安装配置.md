# 02 · 注册账号与安装配置（动手前的准备）

> 这一章帮你把工具备齐：**注册 GitHub → 装 Git → 配置身份 → 配好"钥匙"（让你能往云端传东西）**。
> 跟着做完，你的电脑就具备了和 GitHub 通信的能力。怕命令行？文末有**全程图形界面**的 GitHub Desktop 方案。

---

## 一、注册一个 GitHub 账号

1. 打开 **https://github.com**，点右上角 **Sign up（注册）**。
2. 依次填：
   - **Email**：常用邮箱（用来收通知、找回密码）。
   - **Password**：密码（建议 8 位以上，混合大小写数字）。
   - **Username（用户名）**：⚠️ **重要**——这会成为你的网址 `github.com/你的用户名`，相当于门牌号，**注册后改起来麻烦**，建议用简洁、专业、英文的名字（比如 `lixiaoming`、`xm-li`），别用 `cute_baby_2008` 这种。
3. 按提示完成一个"验证你是人类"的小拼图。
4. 去邮箱点击验证链接，激活账号。

> 💡 学生福利：用**学校邮箱（.edu 等）** 申请 [GitHub Student Pack](https://education.github.com/pack)，能白嫖一堆付费工具和云服务额度。

### 必做：开启两步验证（2FA）

GitHub 现在**强制要求**参与协作的用户开启 **2FA（Two-Factor Authentication，双重验证）**。它的意思是：登录时除了密码，还要再输一个"动态验证码"，防止密码泄露后账号被盗。

- 进入 **Settings（设置）→ Password and authentication → Two-factor authentication**。
- 推荐用**手机验证器 App**（如 Microsoft Authenticator、Google Authenticator、1Password）扫码绑定，之后每次登录新设备时输入 App 上的 6 位动态码。
- ⚠️ **务必保存好"恢复码（recovery codes）"**：截图或抄下来存安全的地方。手机丢了就靠它救命，否则可能永久登不进账号。

## 二、安装 Git（你电脑上的版本控制工具）

回忆第 1 章：**Git 是工具，GitHub 是网站**。注册完账号，还要在自己电脑上装 Git，才能在本地干活。

### Windows

1. 打开 **https://git-scm.com**，点 Download，下载 Windows 版安装包。
2. 双击安装，**一路点 Next 用默认选项即可**（选项很多但默认就是最优解，小白不用纠结）。
3. 装好后，开始菜单里会多出一个 **Git Bash**——这是一个黑底命令行窗口，以后敲 Git 命令就在这里面（比 Windows 自带的 cmd 更好用）。

### macOS

最简单的方式：打开"终端（Terminal）"，输入：

```bash
git --version
```

如果没装，系统会自动弹窗提示你安装开发者工具，点同意即可。或者去 https://git-scm.com 下载安装包。

### Linux（Ubuntu/Debian）

```bash
sudo apt update
sudo apt install git
```

### 验证安装成功

打开命令行（Windows 用 Git Bash），输入：

```bash
git --version
```

看到类似 `git version 2.43.0` 的输出，就说明装好了。✅

> 📌 **第一次见命令行别慌**：它就是个能打字的黑窗口。你输一行命令、按回车，它执行并把结果打出来。命令打错不会爆炸，顶多报个错。

## 三、配置你的身份（告诉 Git "你是谁"）

每次 commit（存档）都会记下"是谁存的"。所以装好 Git 后第一件事，是设置你的名字和邮箱。**在命令行里输入**（把引号里换成你自己的）：

```bash
git config --global user.name "Li Xiaoming"
git config --global user.email "你的邮箱@example.com"
```

- `--global` 表示"全局设置"，对你电脑上所有项目生效，**只需设置这一次**。
- ⚠️ 邮箱**建议和 GitHub 注册邮箱一致**，这样 GitHub 才能把提交正确算到你头上（你的头像才会出现在贡献记录里）。

检查是否设置成功：

```bash
git config --global --list
```

会打印出你刚设的 name 和 email。

> 💡 顺手把默认分支名设成 `main`（现在的行业标准，旧版 Git 默认还是 `master`）：
> ```bash
> git config --global init.defaultBranch main
> ```

## 四、配好"钥匙"：让你的电脑有权限往 GitHub 传东西

这是小白**最容易卡住、也最关键**的一步，请耐心看完。

### 为什么需要这一步？

你往 GitHub 传代码（push）时，GitHub 得确认"你真的是这个账号的主人"。**重点（很多老教程是错的）**：

> ⚠️ **从 2021 年 8 月起，GitHub 不再允许用"账号密码"来推送代码了。** 你必须用下面两种"钥匙"之一：**个人访问令牌（PAT）** 或 **SSH 密钥**。

为什么？因为直接用登录密码不安全（一旦泄露全盘皆输）。这两种方式更安全、可单独吊销。下面二选一即可，**小白推荐方案 A**。

---

### 方案 A：个人访问令牌（PAT）—— 简单，推荐新手

PAT（Personal Access Token）你可以理解成一个"**专门给命令行用的、超长的临时密码**"，可以随时吊销、能限定权限。

1. GitHub 网页右上角头像 → **Settings**。
2. 左侧菜单拉到最底 → **Developer settings**。
3. **Personal access tokens → Tokens (classic) → Generate new token (classic)**。
4. 填写：
   - **Note**：起个名字，如 `my-laptop`，方便以后认出来。
   - **Expiration**：有效期，可选 90 天或更长。
   - **Select scopes（权限）**：勾选 **`repo`**（操作仓库的权限，足够日常用）。
5. 点 **Generate token**，会显示一长串 `ghp_xxxxxxxx...`。

> 🚨 **这串令牌只显示这一次！** 关掉页面就再也看不到了。**马上复制下来**存到安全的地方（密码管理器）。丢了就只能重新生成一个。

**怎么用它？** 以后你 push 时，命令行会弹出来问账号密码：

- Username（用户名）：输你的 GitHub 用户名。
- Password（密码）：**粘贴那串令牌**（不是你的登录密码！）。

输一次之后，系统通常会帮你记住（凭据管理器），后面就不用反复输了。

---

### 方案 B：SSH 密钥 —— 一劳永逸，稍微复杂

SSH 的好处是**配好一次，以后 push/pull 永远不用再输任何东西**。原理是生成一对钥匙：**私钥**留在你电脑（绝不外传），**公钥**放到 GitHub。两者匹配就放行。

1. 生成密钥对（命令行输入，邮箱换成你的）：
   ```bash
   ssh-keygen -t ed25519 -C "你的邮箱@example.com"
   ```
   一路按回车用默认即可（提示设密码可直接回车跳过）。

2. 复制**公钥**内容。公钥文件在 `~/.ssh/id_ed25519.pub`：
   ```bash
   # Mac/Linux
   cat ~/.ssh/id_ed25519.pub
   # Windows (Git Bash) 同上
   ```
   把打印出来的一整行（`ssh-ed25519 AAAA... 你的邮箱` 开头那串）复制下来。

   > ⚠️ 复制的是 `.pub` 结尾的**公钥**！没有 `.pub` 的那个是**私钥，绝对不能给任何人**。

3. 粘贴到 GitHub：**Settings → SSH and GPG keys → New SSH key**，Title 随便起，Key 里粘贴公钥，保存。

4. 测试是否成功：
   ```bash
   ssh -T git@github.com
   ```
   看到 `Hi 你的用户名! You've successfully authenticated...` 就成功了 ✅。

> 📌 用 SSH 时，克隆仓库要用 **SSH 地址**（`git@github.com:用户名/仓库.git`）而不是 HTTPS 地址。GitHub 仓库页的绿色 **Code** 按钮里可以切换 HTTPS / SSH 两种地址，第 4 章会用到。

---

### 方案 A 还是 B？

| | 方案 A：PAT 令牌 | 方案 B：SSH 密钥 |
| --- | --- | --- |
| 难度 | ⭐ 简单 | ⭐⭐ 稍复杂 |
| 体验 | 偶尔要粘贴令牌 | 配好后**永不再输** |
| 适合 | 刚入门、临时用 | 长期、自己的主力电脑 |

> 👉 **建议**：第一次就先用 **方案 A** 跑通，别在配置上耗太久。等用熟了、想一劳永逸，再花十分钟配 **方案 B**。

## 五、怕命令行？用 GitHub Desktop（全程图形界面）

如果你看到黑窗口就头疼，可以装 **GitHub Desktop**——一个官方的**图形界面**软件，点点鼠标就能完成 commit、push、pull、切分支，**完全不用记命令**。

- 下载：**https://desktop.github.com**
- 装好后用你的 GitHub 账号登录，它会**自动帮你配好身份和钥匙**，上面方案 A/B 都可以省了。
- 适合：纯小白、文档/笔记类项目、不写代码只想用 GitHub 管理文件的人。

> 💡 本教程后面仍以**命令行**为主线讲解（因为命令是通用的、面试和教程里都用它），但你完全可以**用 GitHub Desktop 对照着做**——每个命令在它界面上都有对应的按钮。两条腿走路，哪个顺手用哪个。
