# 11 · 在 VS Code 里用 Git（图形界面做日常操作）

> 命令行不是必须的。这一章教你用 **VS Code**——目前最流行的免费代码/文本编辑器——**点鼠标**完成 add、commit、push、pull、切分支、解决冲突。
> 每个按钮我都标了它**对应第 4、5 章的哪条命令**，这样你"会点界面"的同时也"懂背后发生了什么"。

---

## 一、为什么推荐 VS Code

- 免费、跨平台（Windows/Mac/Linux），下载：**https://code.visualstudio.com**
- **内置 Git 功能**，不用装任何东西就能用。
- 改文件、看差异、提交、推送**在同一个窗口完成**，比"编辑器 + 命令行来回切"顺手得多。
- 对小白特别友好：改了哪些文件、哪几行，**用颜色直接标出来**，一目了然。

> 💡 命令行 vs VS Code 不是二选一。很多人**日常用 VS Code 点按钮，偶尔复杂操作回命令行**。两者操作的是同一个 Git 仓库，随时可混用。

---

## 二、打开一个仓库

两种方式：

- **已经在本地的仓库**（比如第 4 章 clone 下来的 `my-notes`）：VS Code 菜单 **File → Open Folder**，选那个文件夹。
- **直接从 GitHub 克隆**：按 `Ctrl+Shift+P`（Mac 是 `Cmd+Shift+P`）打开命令面板，输 `Git: Clone`，粘贴仓库地址，选个本地位置即可。

打开后，左侧第三个图标（像三个点连线的"分叉"图标）就是 **源代码管理（Source Control）** 面板，快捷键 `Ctrl+Shift+G`。日常操作都在这里。

---

## 三、看懂左边那些颜色和字母

打开仓库后，左侧"资源管理器"里文件名会带**颜色和字母标记**，告诉你每个文件的状态：

| 标记 | 颜色 | 含义 | 对应概念 |
| --- | --- | --- | --- |
| **U** | 绿色 | Untracked，新文件，Git 还没管它 | 第 4 章"未跟踪" |
| **M** | 橙/黄色 | Modified，被修改过 | 工作区有改动 |
| **A** | 绿色 | Added，已加入暂存区 | 已 `git add` |
| **D** | 红色 | Deleted，被删除 | —— |

> 一眼就能看出"我这次动了哪些文件"，不用敲 `git status`（不过它本质就是图形化的 `git status`）。

---

## 四、日常核心循环：add → commit → push（全程点鼠标）

打开**源代码管理面板**（`Ctrl+Shift+G`），你会看到一个 **Changes（更改）** 列表，列着所有改过的文件。

### 第 1 步：暂存（= `git add`）

- 把鼠标移到某个文件上，点右边的 **`+`** 号 → 这个文件就被"暂存"了，移到上方 **Staged Changes（暂存的更改）**。
- 想一次暂存全部：把鼠标移到 "Changes" 标题上，点那一行的 **`+`**。

> 🔗 这一步等于命令行的 `git add 文件名` 或 `git add .`

### 第 2 步：提交（= `git commit`）

- 在面板顶部的**输入框**里写 commit message（如 `完善读书清单`）。
- 点上方的 **✓ Commit（提交）** 按钮（或按 `Ctrl+Enter`）。

> 🔗 等于 `git commit -m "完善读书清单"`
> 💡 如果你没先暂存就点提交，VS Code 会贴心地问"要不要把所有改动一起提交？"，确认即可。

### 第 3 步：推送（= `git push`）

提交完，代码还在本地。点面板顶部 **`...`（更多操作）→ Push**，或点底部状态栏那个**同步图标 🔄**（带上下箭头和数字）。

> 🔗 等于 `git push`
> 💡 底部状态栏那个 **🔄 同步** 按钮很万能：它会**先 pull 再 push**，一键把本地和云端对齐。数字代表"有几个提交要上传/下载"。

### 一张对照表（界面操作 ↔ 命令）

| 你在 VS Code 点 | 等于命令 |
| --- | --- |
| 文件旁的 `+` | `git add 文件` |
| "Changes" 旁的 `+` | `git add .` |
| 写信息 + 点 ✓ Commit | `git commit -m "..."` |
| `...` → Push | `git push` |
| `...` → Pull | `git pull` |
| 底部 🔄 同步按钮 | `git pull` + `git push` |

## 五、查看"改了哪几行"（可视化 diff）

在源代码管理面板里**点一下任意改过的文件**，VS Code 会**左右并排**显示：左边是上一版，右边是现在，**改动的行高亮**——绿色新增、红色删除。

> 这就是图形化的 `git diff`，比命令行直观一百倍，提交前扫一眼能避免提交错东西。

---

## 六、切换 / 新建分支（点底部状态栏）

VS Code **左下角状态栏**会显示当前分支名（带个分叉图标，如 `🔀 main`）。

- **点它** → 弹出分支列表，选一个就**切换**过去（= `git switch 分支名`）。
- 列表顶部有 **"+ Create new branch"** → 输名字就**新建并切换**（= `git switch -c 新分支名`）。

> 🔗 对应第 5 章的分支操作，不用记命令。

---

## 七、解决合并冲突（VS Code 的杀手锏）

第 5 章我们手动删 `<<<<`/`====`/`>>>>` 标记解决冲突。VS Code 把这事做得**特别友好**：

当 pull 或 merge 产生冲突，打开那个冲突文件，VS Code 会在冲突位置直接给你几个**可点击的按钮**：

```
  <<<<<<< 你的改动（Current Change）
        [Accept Current Change] [Accept Incoming Change] [Accept Both Changes]
  =======
        对方的改动（Incoming Change）
  >>>>>>>
```

- **Accept Current Change**：留我的（当前分支的）。
- **Accept Incoming Change**：留对方的（合并进来的）。
- **Accept Both Changes**：两个都留。
- 也可以**手动编辑**成你想要的样子。

点完按钮，标记符号自动消失，然后照常**暂存 + 提交**完成合并。比命令行删符号省心多了。

> 💡 还有个 **"Resolve in Merge Editor"** 按钮，会打开一个三栏对比界面（我方 / 对方 / 结果），更适合复杂冲突。

## 八、强烈推荐装一个插件：GitLens

在 VS Code 左侧**扩展（Extensions）**面板搜 **GitLens** 安装。它能：

- 在**每一行代码末尾**显示"这行是谁、什么时候、哪次提交改的"（叫 blame，追责神器）。
- 更强的历史浏览、分支对比、提交搜索。

对想深入理解"代码演变历史"的人非常有用，免费版就够用。

## 九、什么时候还得回命令行？

VS Code 图形界面能覆盖 90% 日常。剩下少数情况命令行更方便：

- 复杂的撤销（`git reset` / `git revert` / `git reflog`，见第 7 章）。
- 批量、脚本化操作。
- 服务器上没有图形界面时。

> 所以**两条腿走路**：日常 VS Code 点点点，特殊情况打开它内置的终端（菜单 Terminal → New Terminal）敲命令，无缝衔接。
