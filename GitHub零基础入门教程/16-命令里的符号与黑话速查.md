# 16 · 命令里的符号与黑话速查（看不懂的"鬼画符"都在这）

> 小白看 Git 命令最崩溃的，不是命令本身，而是里面一堆**没人解释的符号和黑话**：`origin`、`HEAD`、`origin/main`、`HEAD~1`、`git@github.com:`、`-m`、`<分支名>`、开头的 `$`……
> 这一章一个一个翻译成人话。**当字典查，看到不认识的符号就回来翻。**

---

## 一、最坑小白的符号（先看这几个，能省你无数次报错）

### `$` 和 `#`（提示符，不要敲！）

```bash
$ git status
```

很多教程命令前面有个 `$`（或 `#`）。**它是终端的提示符，是自动显示的，不是让你打的！** 你只要敲 `git status`。把 `$` 也复制进去会报 `$: command not found`。

> 🚨 这是小白头号翻车点，详见第 00 章。**本教程代码块不带 `$`，复制即可用。**

### `<...>` 尖括号（占位符，要替换掉）

教程里写：

```bash
git switch -c <分支名>
git clone <仓库地址>
```

`<分支名>`、`<仓库地址>` 是**占位符**，意思是"**这里换成你自己的东西，连尖括号一起删掉**"。比如建一个叫 `login` 的分支，真正敲的是：

```bash
git switch -c login          # ✅ 对
git switch -c <login>        # ❌ 错，别留尖括号
git switch -c <分支名>        # ❌ 错，这是没替换的占位符
```

### `.`（一个点 = 当前文件夹）

```bash
git add .
```

那个点表示"**当前所在的这个文件夹里的所有东西**"。`git add .` = "把当前目录的所有改动都加进暂存区"。日常最常用的写法。

### `..`（两个点 = 上一级文件夹）

```bash
cd ..
```

退回到上一层目录。（注意：和上面 `HEAD~1` 那种"上一个提交"不是一回事，别混。）

### `~`（波浪号 = 你的家目录）

`cd ~` = 回到你的用户主文件夹。`~/Desktop` = 你的桌面。

### `*`（星号，两种含义看场合）

```bash
git branch
* main          # ← 这里的星号表示"你当前所在的分支"
  dev
```

- 在 `git branch` 的输出里，`*` 标记**你现在站在哪个分支**。
- 在 `.gitignore` 等地方，`*` 是**通配符**，`*.log` = "所有以 .log 结尾的文件"。

## 二、Git 里反复出现的"地名"黑话

### `origin`——远程仓库的默认外号

```bash
git push -u origin main
```

`origin` 不是什么关键字，它只是**你 clone 下来的那个 GitHub 远程仓库的默认名字（外号）**。Git 自动给远程仓库起的别名就叫 `origin`，省得你每次打一长串网址。

> 🔑 `git push origin main` = "把 `main` 分支推到那个叫 `origin` 的远程仓库（也就是你的 GitHub 仓库）"。

### `main` / `master`——主分支的名字

- `main` 是**默认主分支**的名字（项目的主线）。
- `master` 是**旧的**默认名，2020 年后 GitHub 改用了 `main`。看到老项目是 `master` 别奇怪，它俩是一回事，只是叫法变了。

### `origin/main`——"云端那条 main 的影子"

```
main           ← 你本地的 main 分支
origin/main    ← Git 记下来的"上次同步时，云端 main 长啥样"
```

带斜杠的 `origin/main` 表示**远程仓库上 `main` 分支的状态**（在你本地的一个"记录/影子"）。当你 `git pull`，就是把 `origin/main` 的新东西合并到你本地 `main`。理解成"本地的 main"和"云端的 main"两条线即可。

### `HEAD`——"你现在站在哪"的指针

`HEAD` 是 Git 用来记录"**你当前所在的位置/提交**"的指针。通常它指向你当前分支的最新提交。你切分支、切提交，`HEAD` 就跟着动。

> 多数时候你不用管它，知道"HEAD = 我现在在这儿"就够了。

### `HEAD~1`、`HEAD~2`、`HEAD^`——往回数提交

```bash
git reset --soft HEAD~1
```

- `HEAD~1` = "**当前位置往回数 1 个提交**"（上一个提交）。
- `HEAD~2` = 往回数 2 个，以此类推。
- `HEAD^` = 也是上一个提交（`^` 和 `~1` 这里基本等价）。

所以 `reset HEAD~1` 就是"退回到上一个提交"。

## 三、那串"乱码"是什么——提交 ID（哈希值）

`git log` 里每个提交前面都有一长串字符：

```
commit a1b2c3d4e5f6a7b8c9d0e1f2a3b4c5d6e7f8a9b0
```

这叫**提交的 ID / 哈希值（hash / SHA）**，是这次提交**独一无二的身份证号**，Git 自动算出来的。

- 你**不用记它、也不用看懂它**。
- 需要指定某个提交时（比如 `git revert <ID>`），用前 **7 位**就够了，如 `a1b2c3d`。
- `git log --oneline` 会只显示前 7 位，更清爽。

## 四、命令里的"小尾巴"——选项 / 参数（flag）

命令后面那些 `-x` 或 `--xxx` 是**选项（flag）**，用来调命令的行为。常见的：

| 选项 | 读法 | 干嘛的 | 例子 |
| --- | --- | --- | --- |
| `-m` | message | 直接带上提交说明 | `git commit -m "说明"` |
| `-u` | upstream | 建立本地分支和远程的关联（设一次以后省事） | `git push -u origin main` |
| `-c` | create | 新建（分支） | `git switch -c login` |
| `-d` | delete | 删除（分支） | `git branch -d login` |
| `-b` | branch | 新建分支（clone/checkout 时） | `git checkout -b login` |
| `-a` | all | 所有 | `git add -a`、`ls -a` |
| `--global` | 全局 | 对所有项目生效 | `git config --global ...` |
| `--amend` | 修改 | 改最近一次提交 | `git commit --amend` |

> 💡 规律：**单个字母用一个横杠** `-m`，**完整单词用两个横杠** `--global`。很多有简写也有全称，如 `-m` ≈ `--message`。

## 五、克隆地址里的符号：HTTPS vs SSH

你会看到仓库地址有两种长相：

```
HTTPS:  https://github.com/用户名/仓库名.git
SSH:    git@github.com:用户名/仓库名.git
```

拆解一下：

- 结尾的 **`.git`**：表示"这是一个 Git 仓库地址"，clone 时带不带都行，GitHub 给的默认带上。
- SSH 那串 **`git@github.com:`**：`git@` 是登录用户，`github.com` 是服务器，**冒号 `:`** 后面跟仓库路径。长得怪，但照抄就行。
- 用 PAT 令牌选 HTTPS，用 SSH 密钥选 SSH（见第 02 章）。

## 六、GitHub 网站上的符号黑话

| 符号 | 在哪见 | 意思 |
| --- | --- | --- |
| `#12` | Issue/PR、评论里 | **第 12 号** Issue 或 PR。打 `#` 会自动联想编号，点击可跳转 |
| `@用户名` | 评论、说明里 | **@ 提及**某人，会给他发通知（和微博 @ 一样） |
| `Closes #12` | PR 说明里 | 这个 PR 合并后**自动关闭** 12 号 Issue |
| ✅ / ❌ | PR、提交旁 | 自动检查（Actions/CI）**通过 / 失败**（见第 12 章） |
| 🟢 `main` ▾ | 仓库页 | 当前查看的**分支**，点开可切换 |
| `v1.2.0` | Releases/Tags | **版本号 / 标签**，标记一个正式发布的版本 |
| `+128 −34` | PR/提交 | 这次改动**新增 128 行、删除 34 行** |

## 七、一句话翻译几条"长命令"（活学活用）

把前面学的拼起来，再看这些命令就不懵了：

```bash
git push -u origin main
# 翻译：把(push) 本地 main 分支，推到(origin 这个远程仓库)，
#       并建立关联(-u)，以后直接 git push 就行。

git commit -m "修复登录bug"
# 翻译：把暂存区的改动存档(commit)，附带说明(-m)"修复登录bug"。

git switch -c fix-typo
# 翻译：新建(-c) 一个叫 fix-typo 的分支，并切换过去(switch)。

git reset --soft HEAD~1
# 翻译：退回(reset)到上一个提交(HEAD~1)，但保留改动(--soft)。

git clone git@github.com:torvalds/linux.git
# 翻译：用 SSH 方式，把 torvalds 名下的 linux 仓库整个下载(clone)到本地。
```

> 🔑 **看长命令的窍门**：从左往右拆成"**主命令 + 选项 + 对象**"三块，每块对照本章查意思，拼起来就懂了。
