# 14 · 新手十万个为什么（你不敢问的朴素问题，这里都答了）

> 这一章不讲操作，专门回答小白心里**那些"问出来怕被笑话"的朴素疑问**。按主题分好了，扫一眼标题，挑你正纠结的看。
> 答案都尽量给"一句话结论 + 解释"，看完心里就踏实了。

---

## 一、关于"公开/隐私/安全"（最多人担心的）

**Q：我建的仓库选了 Public（公开），是不是全世界都能看到我的代码？**
A：**是的**，Public 仓库任何人都能浏览、下载你的代码和提交历史（但**只有你和你授权的人能改**）。学习练手用 Public 完全没问题。不想被看见就选 **Private（私有）**，只有你自己看得到。

**Q：公开了，别人会不会偷我的代码/创意？**
A：别人能看、能下载、能 Fork，这是开源的常态。但①没有你的授权他们改不了**你的**仓库；②真正有价值的是你持续的更新和维护，不是一份静态代码。**真要保密的东西（商业项目、含密钥的）就放 Private**。

**Q：Public 能改回 Private 吗？反过来呢？**
A：**都可以**，随时在仓库 **Settings → 最底部 Danger Zone → Change visibility** 切换。注意：改成 Private 后，之前别人给的 Star、Fork 关系可能会丢失。

**Q：我不小心把密码/密钥提交上去了，删掉文件就安全了吗？**
A：**不安全！** 文件即使删了，**它还留在提交历史里**，翻历史就能看到。正确做法：**第一时间去把那个密码/密钥作废、重置**（当它已泄露），再处理仓库。详见第 07 章"误传敏感文件"。预防：push 前用 `git status` 看一眼传了啥，敏感文件写进 `.gitignore`（第 04 章）。

**Q：我的提交记录里有我的真实邮箱，会被人拿去发垃圾邮件吗？**
A：有可能。GitHub 提供一个**隐私邮箱**功能：Settings → Emails → 勾选 "Keep my email addresses private"，会给你一个 `数字+用户名@users.noreply.github.com` 的地址，把 `git config --global user.email` 设成它，提交就不暴露真实邮箱了。

## 二、关于"钱和限制"

**Q：用 GitHub 要花钱吗？**
A：**个人学习、做项目，免费版完全够用。** 免费就能建**无限个**公开和私有仓库、无限协作者。付费版（Pro/Team）主要是给企业更多高级功能和额度，小白用不着。

**Q：仓库大小有限制吗？**
A：有软性建议：单个仓库最好别超过 **1GB**，单个文件别超过 **100MB**（超 50MB 会警告，超 100MB 直接拒绝）。所以**别往 Git 里塞大视频、大数据集、几百兆的安装包**。要存大文件有专门方案（Git LFS），但小白一般用不到。

**Q：GitHub Actions（自动化）免费吗？**
A：**公开仓库免费用**。私有仓库每月有一定免费分钟数，超了才计费，个人用基本用不完。见第 12 章。

## 三、关于"删除/丢失/恢复"

**Q：我把本地电脑上的项目文件夹删了，GitHub 上的还在吗？**
A：**还在。** 本地和云端是两份。删了本地，重新 `git clone` 一下就又下回来了——这正是 GitHub 当"云备份"的好处。

**Q：反过来，我在 GitHub 上把仓库删了，本地的还在吗？**
A：**本地还在**（本地是独立的一份）。但你就不能再 push 了（远程没了）。

**Q：误删了 GitHub 上的仓库，能恢复吗？**
A：短时间内**可能可以**。Settings → 找到 "Deleted repositories" 或在 90 天内通过特定页面恢复（有时限）。但别指望，**删之前三思**。

**Q：我 `commit` / `reset` 之后东西好像没了，能找回吗？**
A：**大概率能。** Git 极难真正丢东西。用 `git reflog` 这个"终极后悔药"几乎能找回任何"丢失"的提交，详见第 07 章。

**Q：怎么彻底删除我的 GitHub 账号？**
A：Settings → 最底部 → Delete account。**不可逆**，所有仓库一起没，慎重。

## 四、关于"协作/社交"

**Q：我 Star（点星）或 Fork 了别人的项目，对方会知道吗？**
A：**会**。Star 会显示在你"给谁点过星"的列表里（公开），Fork 也会在原项目的 Fork 列表里显示你。这是正常社交，没什么不好意思的。

**Q：一个仓库最多能有多少协作者？**
A：免费版私有仓库协作者基本也是无限的（早期有限制，现已放开）。公开仓库谁都能 Fork + 提 PR，不需要先加协作者。

**Q：我给开源项目提了 PR，作者一直不理我怎么办？**
A：很常见，别往心里去。作者可能忙、可能项目不活跃了。可以礼貌地 @ 一下他催更，或者就让它放着。**你的 PR 记录本身就是你的贡献证明**。

**Q：贡献者（Contributor）是怎么算的？我也能成为某大项目的贡献者？**
A：**你给某项目提的 PR 被合并，你就是该项目的 Contributor 了**，名字会出现在贡献者列表。从改个错别字开始，人人都能贡献，见第 06 章和第 13 章的练习。

## 五、关于"我到底需不需要会XX"

**Q：用 GitHub 必须会编程吗？**
A：**不必须。** 很多人用 GitHub 管理笔记、文档、电子书、设计稿、写作。本教程第 03、09、10 章全是非编程也能玩的。当然，会点编程能解锁更多玩法。

**Q：必须会命令行吗？**
A：**不必须。** 网页（第 03 章）、GitHub Desktop（第 02 章）、VS Code（第 11 章）都能图形化完成 90% 的事。命令行是"通用语言"，会了更方便，但不是门槛。

**Q：我英语不好，能用 GitHub 吗？**
A：能。GitHub 界面可在 Settings → Appearance 切**简体中文**。文档也有中文版（docs.github.com/zh）。命令是固定的几条，照抄即可。

## 六、关于"国内访问"

**Q：GitHub 经常打不开/特别慢怎么办？**
A：国内访问 GitHub 有时不稳定。几个办法：①多刷新/换个时间；②练手可以先用国内的 **Gitee（码云）**，操作几乎一样（见第 01 章）；③网络工具因人而异，自行解决。**学概念不受影响**，本教程命令在哪个平台都通用。

**Q：clone 大项目特别慢/断了怎么办？**
A：可以加 `--depth 1` 只下载最新版本（不要全部历史），快很多：`git clone --depth 1 <地址>`。

## 七、关于"日常习惯"

**Q：一天提交（commit）很多次，正常吗？会不会太频繁？**
A：**非常正常，鼓励！** 提交是免费的、本地的。小步快跑、每完成一个小改动就提交一次，历史更清晰、出问题更好回退。别攒一大堆改动才提交一次。

**Q：commit message（提交说明）必须写英文吗？**
A：**不必须，中文完全可以。** 重点是**写清楚这次改了什么**，语言其次。团队里跟团队约定走。

**Q：main 和 master 到底啥区别？**
A：**同一个东西，主分支的名字。** `master` 是旧默认名，2020 年起 GitHub 改用 `main`。看到哪个都一样对待。

**Q：我能离线（没网）工作吗？**
A：**能！** Git 是本地工具，`add`、`commit`、切分支、看历史**全程不用网**。只有 `push`（上传）和 `pull`（下载）才需要网。在飞机上照样能 commit，落地了再 push。

**Q：手机上能用 GitHub 吗？**
A：能。有官方 **GitHub 手机 App**（iOS/安卓），可以看代码、回 Issue、审 PR、合并。**但写代码/复杂操作还是电脑方便**，手机适合碎片时间看通知、回复。

## 八、还是没找到答案？

- **看官方中文文档**：docs.github.com/zh —— 最权威。
- **直接搜**：把你的问题（中文或英文）丢进搜索引擎，大概率前人早问过。
- **问 AI**：把报错或疑问描述清楚，让 AI 帮你解释。
- **去问社区**：在相关项目的 Issue 区、技术论坛礼貌提问。

> 🔑 **心态最重要**：没有"蠢问题"。每个高手都从"GitHub 是啥"问起。大胆试、不怕错——Git 几乎什么都能撤销，你很难真正搞坏什么。
