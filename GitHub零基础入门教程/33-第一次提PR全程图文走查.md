# 33 · 第一次提 PR 全程图文走查（截图级，每一屏都画给你）

> "给开源项目提 Pull Request"是小白最想做、又最害怕的一件事。[第 06 章](./06-团队协作-Fork与PR.md) 讲了原理和步骤，这一篇**把每一屏画出来**——你会看到什么界面、鼠标点哪、框里填啥、提交后发生什么、被要求修改怎么办。
> 跟着走一遍，你的人生第一个 PR 就诞生了。**全程用网页 + GitHub Desktop，最适合零基础。**

> 🧭 图例：`[按钮]` 可点；`▾` 下拉；`← 点这`/`← 填这` 是指引；`📺` 是"你会看到的画面"。

---

## 准备：选一个练手项目

我们用一个**专门给新手练 PR** 的著名项目演示：**first-contributions**。它的 README 会引导你把自己的名字加进一个列表——这是全球新人提交第一个 PR 的传统。

> 打开浏览器搜 **`first-contributions`**，进入那个 Star 很多的仓库（`firstcontributions/first-contributions`）。下面以它为例；换成任何项目，流程都一样。

整个流程一张图先看全貌：

```
① Fork          ② Clone        ③ 开分支      ④ 改+提交     ⑤ 推送      ⑥ 发PR        ⑦ 等审查/合并
(抄到我账号) → (下载到本地) → (开沙盒) → (改文件存档) → (传到我Fork) → (申请合并) → (被合并🎉)
   网页点         Desktop        Desktop      Desktop       Desktop       网页          网页
```

---

## 第 ① 步：Fork —— 把项目抄一份到自己账号

你没有这个项目的写权限，所以先 Fork 一份属于自己的副本。

```
📺 项目主页右上角：
   [👁 Watch ▾]   [🍴 Fork ▾]   [⭐ Star ▾]
                      ↑ 点 Fork（不是右边的小三角，点 Fork 字样）

📺 弹出 "Create a new fork" 页面：
┌─────────────────────────────────────────────┐
│ Create a new fork                            │
│                                              │
│ Owner *              Repository name *        │
│ [你的用户名 ▾]  /  [first-contributions   ]   │ ← 一般默认即可，别改
│                                              │
│ Description (optional)  [...................] │
│                                              │
│ ☑ Copy the main branch only                  │ ← 保持勾选                  │
│                                              │
│              [ Create fork ] ← 点这个绿钮      │
└─────────────────────────────────────────────┘

📺 等几秒，页面跳转到：
   github.com/你的用户名/first-contributions
   注意左上角现在是【你的用户名】，下面有一行小字：
   "forked from firstcontributions/first-contributions"  ← 看到这行就对了！
```

> ✅ **成功标志**：网址变成 `github.com/你的用户名/...`，且有"forked from..."字样。
> ❓ **常见疑惑**：Fork 是在 GitHub 云端复制，你电脑上还没有任何东西——下一步才下载到本地。

---

## 第 ② 步：Clone —— 把你的 Fork 下载到电脑

用 GitHub Desktop（[第 20 章](./20-GitHub-Desktop完全图解.md)），最省事。

```
📺 在【你的 Fork 页面】点绿色 [<> Code ▾]，弹出：
┌──────────────────────────────────────┐
│ [Local] [Codespaces]                  │
│  ( HTTPS )( SSH )                      │
│  https://github.com/你/first-...git    │
│                                       │
│  [💻 Open with GitHub Desktop] ← 点这个 │
│  ⬇ Download ZIP                        │
└──────────────────────────────────────┘
   点 "Open with GitHub Desktop"，浏览器会问"要打开 GitHub Desktop 吗？"→ 允许

📺 GitHub Desktop 弹出 "Clone a repository"：
┌──────────────────────────────────────┐
│ Clone a repository                    │
│ URL: github.com/你/first-contributions │
│ Local path: [C:\Users\你\Documents\...] │ ← 存哪，默认即可
│              [ Clone ] ← 点这个         │
└──────────────────────────────────────┘
```

> ✅ **成功标志**：GitHub Desktop 顶部左上 "Current Repository" 显示 `first-contributions`。
> 💡 想看下载到哪了？菜单 **Repository → Show in Explorer/Finder**。
> 🔗 命令行等价：`git clone https://github.com/你/first-contributions.git`

---

## 第 ③ 步：开一个分支 —— 在沙盒里改，不动 main

```
📺 GitHub Desktop 顶部中间：
   [ Current Branch: main ▾ ] ← 点这个下拉
┌──────────────────────────────────────┐
│ 🔍 [搜索/输入新分支名........]          │
│    Default Branch                     │
│    ✓ main                             │
│                                       │
│    [ New branch ] ← 点这个             │
└──────────────────────────────────────┘

📺 弹出 "Create a branch"：
┌──────────────────────────────────────┐
│ Name: [add-my-name           ]        │ ← 填个有意义的名字
│ Based on: main                        │
│        [ Create branch ] ← 点这个      │
└──────────────────────────────────────┘
```

> ✅ **成功标志**：顶部 "Current Branch" 现在显示 `add-my-name`。
> 🔑 **为什么开分支**：保持 main 干净，你的改动隔离在分支里，这是专业习惯（[模型 10](./25-必学模型/02-操作模型.md)）。
> 🔗 命令行等价：`git switch -c add-my-name`

---

## 第 ④ 步：改文件 + 提交（commit）

按 first-contributions 的 README 说明，要在 `Contributors.md` 里加上你的名字。

```
📺 ① 用编辑器打开文件改。GitHub Desktop 菜单：
   Repository → Open in Visual Studio Code（或 Show in Explorer 用记事本打开）
   在 Contributors.md 末尾加一行：  - 你的名字 (https://github.com/你的用户名)
   保存。

📺 ② 切回 GitHub Desktop，左侧 "Changes" 自动列出你改的文件：
┌────────────────────────┬─────────────────────────────┐
│ Changes (1)            │  Contributors.md             │
│ ☑ Contributors.md      │  ...                         │
│                        │ + - 你的名字 (https://...)   │ ← 绿色=你加的行
│                        │                              │
│ ┌────────────────────┐ │                              │
│ │Summary(required)   │ │                              │
│ │[加上我的名字       ]│ │ ← 填提交说明                  │
│ │Description         │ │                              │
│ │[                  ]│ │                              │
│ └────────────────────┘ │                              │
│ [ Commit to add-my-name]│ ← 点这个蓝钮                 │
└────────────────────────┴─────────────────────────────┘
```

> ✅ **成功标志**：点完 Commit 后，左侧 Changes 列表清空（改动已存档进本地分支）。
> ⚠️ **注意**：确认按钮上写的是 `Commit to add-my-name`（提交到你的分支），**不是** `Commit to main`。
> 🔗 命令行等价：`git add .` + `git commit -m "加上我的名字"`

---

## 第 ⑤ 步：推送（push）到你的 Fork

提交只到了本地，要传到 GitHub 上你的 Fork。

```
📺 GitHub Desktop 顶部右边按钮现在变成：
   [ Publish branch ]  ← 第一次推新分支显示这个，点它
   （之后再推会显示 [ Push origin ↑1 ]）
```

> ✅ **成功标志**：按钮变回 "Fetch origin"，且出现一个蓝条提示 "Create Pull Request"。
> 🔗 命令行等价：`git push -u origin add-my-name`

---

## 第 ⑥ 步：发起 Pull Request（核心步骤）

```
📺 方式A：GitHub Desktop 推送后会出现蓝条：
   ┌──────────────────────────────────────────┐
   │ Successfully published! 🎉                 │
   │            [ Create Pull Request ] ← 点它   │
   └──────────────────────────────────────────┘
   它会自动打开浏览器到 PR 创建页。

📺 方式B：或直接去你的 Fork 网页，会看到黄条：
   ┌──────────────────────────────────────────┐
   │ 🟡 add-my-name had recent pushes ...       │
   │            [ Compare & pull request ] ← 点它│
   └──────────────────────────────────────────┘
```

接下来是**最关键的一屏**，务必看懂方向：

```
📺 PR 创建页（Open a pull request）：
┌────────────────────────────────────────────────────────────┐
│ Open a pull request                                         │
│                                                             │
│  base repository: firstcontributions/first-contributions ▾  │ ← 合并进【原项目】
│  base: main  ◄──  head repository: 你/first-contributions ▾  │
│                   compare: add-my-name ▾                    │ ← 来自【你的分支】
│  ↑↑↑ 确认这个方向：左边是目标(原项目main)，右边是你的改动 ↑↑↑   │
│                                                             │
│  Title: [ 加上我的名字到贡献者列表            ]              │ ← 一句话标题
│  ┌─────────────────────────────────────────────────────┐   │
│  │ Write   Preview                                      │   │
│  │ 按照 README 指引，把我的名字加进 Contributors.md。     │   │ ← 说明：做了啥
│  │                                                      │   │
│  └─────────────────────────────────────────────────────┘   │
│                                                             │
│              [ Create pull request ] ← 点这个绿钮            │
└────────────────────────────────────────────────────────────┘
```

> ✅ **成功标志**：点完跳转到 PR 页面，顶部有个绿色的 `Open` 标记，标题是你填的。**你的第一个 PR 诞生了！** 🎉
> ⚠️ **最容易错的地方**：`base` 必须是**原项目**（firstcontributions/...），`compare` 是**你的分支**。方向反了就成了"把原项目合并进你的 Fork"，不对。一般默认就是对的，确认一下即可。
> 🔗 命令行没有"发 PR"，PR 是 GitHub 网页功能（或用 `gh` CLI）。

## 第 ⑦ 步：读懂 PR 页面 + 等待结果

提交后你会进入 PR 页面，认认每个部分：

```
📺 PR 页面：
┌────────────────────────────────────────────────────────────┐
│ 加上我的名字到贡献者列表  #4521        [🟢 Open]              │ ← 标题+编号+状态
│ 你的用户名 wants to merge 1 commit into ...:main from ...     │
├────────────────────────────────────────────────────────────┤
│ [💬 Conversation] [⊙ Commits 1] [✓ Checks] [📄 Files changed]│ ← 四个标签
├────────────────────────────────────────────────────────────┤
│ 💬 Conversation（总讨论区）：                                 │
│   你的 PR 说明显示在这                                        │
│   ── 下面会出现：自动检查结果、维护者的评论、合并按钮 ──        │
│                                                             │
│   🟡 Some checks haven't completed yet  (自动检查在跑)        │
│   或 ✅ All checks have passed          (检查通过)            │
└────────────────────────────────────────────────────────────┘
```

四个标签是什么：
- **Conversation**：总讨论区，所有评论、状态都在这。
- **Commits**：你这个 PR 含哪几次提交。
- **Checks**：自动化测试（CI）结果，✅ 或 ❌。
- **Files changed**：逐行 diff——**维护者在这里审查你的代码**。

接下来会发生三种情况之一：

### 情况 A：直接被合并 🎉

```
📺 维护者点了 Merge，PR 状态变成：
   [🟣 Merged]   "你的用户名's commit was merged into main"
```
**恭喜！你正式成为这个项目的 Contributor 了！** 你的名字进了它的贡献者列表。

### 情况 B：维护者留了修改意见

```
📺 在 Conversation 或 Files changed 里出现评论：
┌──────────────────────────────────────────┐
│ 🧑 maintainer commented                    │
│ 名字前面少了个连字符，麻烦改成 "- 名字"。   │
│ 这样格式才统一。                            │
└──────────────────────────────────────────┘
```
**别慌，也别觉得被否定**（[案例 9](./30-真实案例库.md)）。怎么改：

```
📺 回到 GitHub Desktop，确认还在 add-my-name 分支：
   ① 改文件 → 保存
   ② Summary 填 "按评审意见修正格式" → Commit to add-my-name
   ③ 点 [ Push origin ] 推送
   ── 你的新提交会【自动出现在同一个 PR 里】，不用重新开 PR！──
```
推送后，去 PR 页面回复维护者一句（礼貌）：

```
📺 Conversation 底部评论框：
   [ 已按建议修正，麻烦再看下，谢谢！(PTAL) ]   [ Comment ]
```

### 情况 C：被关闭（Closed）

维护者觉得不需要，会 Close。**这很正常**，礼貌道谢即可，换个项目再来。你的尝试本身就是经验。

## 🆘 各步骤常见卡点速查

| 卡在哪 | 现象 | 怎么办 |
| --- | --- | --- |
| Fork 后 | 找不到自己的副本 | 看网址是不是 `github.com/你的用户名/...`；去你主页 Repositories 里找 |
| Clone | "Open with Desktop"没反应 | 先装好 GitHub Desktop 并登录（[第 20 章](./20-GitHub-Desktop完全图解.md)）；或复制 HTTPS 地址手动 Clone |
| 提交 | 按钮写的是 Commit to **main** | 你没切到分支！回第 ③ 步切到 `add-my-name` 再提交 |
| 推送 | 报认证失败 | Desktop 一般自动配好；命令行的话用 PAT 令牌（[第 02 章](./02-注册账号与安装配置.md)） |
| 发 PR | base/compare 方向反了 | base=原项目 main，compare=你的分支，别搞反 |
| 发 PR | 找不到 "Create Pull Request" | 去原项目或你的 Fork 页点 [Pull requests] → [New pull request] |
| 改完 | 不知道怎么更新 PR | 在**同一分支**继续 commit + push，PR 自动更新，别新开 |
